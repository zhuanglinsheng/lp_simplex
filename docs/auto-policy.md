# AUTO 调度架构

简体中文 | [English](./auto-policy_en.md) | [文档](./README.md)

AUTO 在一个累计工作预算内组合 Dual、BDA 和 Tableau，保留经过审核的候选，并安排恢复。它是调度器；模型表示、方向实现和 LU/QR 后端不是同层算法。

## 源码职责与依赖方向

| 所有者 | 责任 |
| --- | --- |
| [simplex_auto.c](../src/core/simplex_auto.c) | 唯一推进 AUTO 状态；调用、计费、审核、候选提交和最终组装 |
| [simplex_auto_policy.c](../src/core/simplex_auto_policy.c) | 根据只读证据提出触发原因、路线、预算和优先序游标 |
| [simplex_auto_routes.c](../src/core/simplex_auto_routes.c) | 能力/模型/资源准入，以及算法和初始化器的调用适配 |
| `src/runtime` | 规范模型、身份、配置快照、进度桥接、执行履历和失败账本 |
| `src/dual`、`src/bda`、`src/tableau` | 独立算法入口、调用状态、迭代、数值保护和数学认证 |
| `src/presolve` | 约化规则、恢复记录与只读代数映射 |
| `src/basis`、`src/matrix`、`src/common` | 分解、稀疏存储、共享算术和内部政策 |

算法和 runtime 不包含 core 私有头；只有主控包含 `simplex_auto_state.h`。runtime 可引用算法的纯数据诊断类型、配置解析和诊断名称，以及 presolve 的只读映射，但不进入完整求解。Dual 内的退化监视与 BDA 求解器是两个机制。

`python3 tools/check_architecture.py` 检查这些包含边界。它不代替运行期身份或数学审核。

## 入口与调用流程

私有入口为 `simplex_auto_solve`。绑定对象分别描述内核、路线和 cover 能力；初始化器与输出履历独立传入。NULL 绑定对象选择生产默认；显式对象中的缺失回调保持缺失。必需 Dual 不存在时，在分配候选或数值调用前返回能力拒绝；缺失可选能力不预留其预算。

流程如下：

1. 检查可调用能力、模型条件及工作区；必要时尝试 cover。
2. 授权首次 Dual，允许在活状态内根据进展续跑或让出。
3. Dual 让出且没有可行点时，可调用原模型 NNLS 初始化器。
4. 按下表的前进游标尝试恢复，每个配置在一次 AUTO 中至多一次。
5. 将剩余预算交给最终 Dual，最后组装退出状态和返回点。

| 恢复顺序 | 配置与目的 | 额外前提 |
| --- | --- | --- |
| Singleton | 特殊单列结构的对偶化求解 | 界、行类型和正负列配对满足要求；已有初始化点可跳过 |
| 原生隐式 BDA | 在原生界上推进或优化可行点 | 表示及后端资源可用 |
| 原生显式 BDA | 替换原生隐式 oracle | 对应隐式调用明确报告 oracle 故障 |
| 标准形基方向 BDA | 使用标准形及基方向 | 标准形转换与 QR 资源可用 |
| 标准形隐式 BDA | 替换方向方法 | 标准形适用；可继承经审核的点 |
| 标准形显式 BDA | 替换标准形隐式 oracle | 对应隐式调用明确报告 oracle 故障 |
| Tableau | 改用两阶段单纯形 | 稠密化资源可用 |

这些是复合执行配置，不是七种公开算法。通用精度错误、预算结束或分解失败不能单独授权显式 oracle 替换。算法能力清单见[功能索引](./features.md)。

## 预算与阶段完成协议

工作量是算法迭代计数，不是 CPU 秒。令剩余工作为 R、需保留机会的路线数为 k、观察窗口 Q=1024：恢复预留为 `min(R/2, k*Q)`，实现先检查范围再做乘法。

- cover 仅在宽度和预算满足策略时取得 R/2。
- 首次 Dual 为可用恢复路线及最终 Dual 保留观察窗口；没有恢复路线时获得全部剩余工作。
- 初始化器在预留后最多取得 8Q。
- 原生 hybrid 保留后续恢复机会；其他恢复按可用路线均分机会，最终 Dual 使用全部余量。

准确公式由 [policy](../src/core/simplex_auto_policy.c) 和[数值政策](./numerical-policy.md)维护。内核报告本次相对工作，主控只扣一次；嵌套服务汇总包含子工作，不能与父工作再次相加。

每个尝试共用完成协议：调用 → 计费 → 独立审核 → 判终 → 记录 → 提交候选和证据。原始返回、实际扣账和审核结论分别保存。负数或超授权报告按整笔授权保守扣账，撤销该次产出权限；模型身份变化时先拒绝交接，再读取坐标。

## 特征提取与在线重分类

AUTO 的特征提取分布在路线准入、runtime 输入审核和算法内观察器中，尚不是一个预测最佳算法的统一分类器。结构特征用于判断能否调用；动态特征用于判断当前调用是否值得继续。通过全部基准只能验证已覆盖的输入，不能证明任意 LP 都能被预先正确分类。

| 特征 | 提取位置与含义 | 调度权限 |
| --- | --- | --- |
| 行类型、变量界、单列正负配对 | `simplex_auto_routes.c`，直接检查代数前提 | 开放或拒绝特定路线 |
| 标准形扩张、非零数、稠密工作区 | 表示转换前估算存储；不预测稀疏分解填充 | 资源准入，不是收敛预测 |
| 原始残差总量、违反数量、可行目标、下界、对偶残差 | `simplex_stage_observe`，从不可变调用输入独立重算；附带空间、epoch、工作和证据资格 | 同一度量、与阶段目标相关的真实进展可复核工作指标停滞；度量变化另行重新建基 |
| 工作残差、Phase、成本／界 epoch、重复状态 | Dual 活状态 | 续跑、重新审核、数值退出或循环退出 |
| 固定输入目标势、绝对项和、成本漂移 | Dual 的不可行迭代点；只表示搜索进展 | 仅复核 Phase-I 停滞，不能认证目标或下界 |

工作残差停滞时，只用与当前阶段目标相关的独立输入进展复核：Phase I 使用原始残差和违反数量，最优性清理使用可行目标及对偶残差。单独下界改善不复核停滞，因为近零基线上的相对改善可在目标单位下任意小，也不能证明接近原始可行。首次得到可行点或下界只在度量变化时建立一次基线，不能代替已有度量上的真实改善。数值失败和重复状态的退出不能被进展信号覆盖。新测量、同一工作点重复采样、epoch 改变本身均不是进展。

Phase-I 的目标势采用 `V=sum(c_input[j]*x[j])`，不含目标常数，基本变量读取当前基值。尺度为 `A=sum(abs(c_input[j]*x[j]))`，成本漂移为 `D=sum(abs((c_work[j]-c_input[j])*x[j]))`。每次采样的搜索不确定量包含 D、按运算维度计算的舍入留量和既有对偶容差留量。V 必须超过历史峰值；相对上次合格基线的累计增量还须超过两次采样的不确定量之和及 `1%*max(A_now,A_baseline)`。界 epoch 改变只重建基线，不续租。严重抵消、成本漂移或非有限值使该可选信号失效。

V 在原始不可行点上求值，因此不是可行目标，也不是认证下界；成本漂移留量同样不是基求解误差的完整区间证明。它只允许在原累计预算内保留活基，不能放宽终止审核。观察发生在已有租约边界，增加线性扫描，不增加分配。生产诊断输出势、尺度、不确定量及输入进展位；关闭输出不会改变决策。

### 保留的启发式及其边界

| 政策 | 当前依据与局限 |
| --- | --- |
| 128 工作观察量、初始 8 个观察量 | 确定性地摊销观察成本；不是由模型推导的最优窗口 |
| 1% 累计进展门槛 | 沿用共享搜索政策，过滤微小改善；是启发式，不是收敛定理 |
| 租约倍增、恢复预留 | 有进展就延长同一活状态；总预算和后续机会始终有限，不预测剩余求解时间 |
| cover 宽度 32 倍及至少 16 次行规模工作量 | 限制可选受限列搜索的摊销成本；代数适用性仍需另外检查，尺寸比本身不能证明收益 |
| 原模型初始化器的展开行数大于原行数 2 倍、最多 8Q | 有限初始化成本的经验门槛；另须实际标准形更小和输入审核，不代表超过阈值必然更快 |
| 固定恢复次序 | 保证有限、可解释的后备路线；还没有跨算法可比的单位工作收益模型 |

本次不通过放大窗口、降低进展门槛、放宽认证或增加模型名称分支改善通过率。进一步替换这些启发式需要反例、表示／单位变换检查和四套数据回归。尤其不能直接比较 Dual 主元次数与 PDHG 步数，或只凭残差斜率预测求解完成时间，再据此重新分配全部预算。

## 候选、检查点与终止

| 产出 | 接纳条件 | 权限 |
| --- | --- | --- |
| 可行点 | 输入身份一致，坐标有限，独立复算可行性和目标 | 可保留、比较并作为后续种子；不自动表示最优 |
| NNLS 初始化点 | 原模型与约化模型均通过审核，工作合法 | 仅点候选；不导出基、分解、对偶或下界 |
| Dual 基提示 | 输入对象/上下文/模型/版本/存储匹配，索引与状态合法 | 导入后重新分解、重算与分类；不保存活分解 |
| 行乘子或下界 | 当前模型、符号和坐标空间匹配，审核有效 | 仅保留已声明的资格；辅助模型诊断不等于输入证书 |

身份包含输入对象、活上下文、模型编号、revision、维度及数学存储指针。调用中的模型与映射不可变；原地内容修改必须标记 revision，指针检查不扫描全部系数。受限列交接另见[列模型契约](./column-handoff.md)。

成功须同时满足内核终止认证和主控输入审核。不可行/无界证据由相应算法负责；已有容差可行点会否定冲突的不可行声明。路线耗尽与预算耗尽分别返回精度失败和迭代上限，可保留最佳可行点。最终报告重新描述实际返回点，不沿用被替换点的对偶诊断。

## 状态与因果

`AutoRuntime` 拥有累计工作、游标、候选、检查点和决策证据；`AutoAttempt` 保存单次原始产出与审核；`AutoHistory` 和执行事件只输出诊断。关闭、写满或重置履历不会改变数值准入。

每次切换分别记录前提、目的、触发原因、点来源和基来源。例如，Dual 让出可触发 hybrid，而它使用的点来自 NNLS；显式 oracle 的原因必须来自对应隐式故障，不能指向最后一个无关动作。准入数组只保存最近一次观察，不是完整状态变更日志。

跨回调的引用绑定活上下文、事件 token、类型及模型，使用前重新核对；同址重置或槽位复用会丢失出处，不会产生新数学资格。父调用、触发原因和数值产出来源是不同关系。

## 跨层身份与恢复链

| 层级 | 触发与职责 | 预算和结果规则 |
| --- | --- | --- |
| Dual 后端 | 默认后端提前数值失败时，尝试一次内部 LU | 同一模型、剩余授权；数学分类或资源失败不触发此替换 |
| AUTO | 当前路线未终止且后续能力可用 | 前进游标和累计授权；候选、点源与基源各自审核 |
| 原模型恢复 | 约化/还原结果未通过原模型接纳 | 至多一次冷重解，沿用调用者算法和根配置，不递归后求解 |
| 进度存档 | 非最优退出时发现更好的原模型可行点 | 可替换返回点，保留已用工作，清除不再适用的对偶诊断 |

代数恢复只重放 presolve journal，不求解、不审核，也不消费迭代预算。缩放桥接恢复原单位；不可逆转换退回精确借用的输入。检查点和进度桥接均绑定其实际输入，不能仅凭维度相同复用。

后端事件报告局部工作，`POINT_SELECTION` 报告完整调用的累计工作。选点与两次尝试同属调用方，触发重试与返回点来源分开记录；不得将累计摘要再加到尝试之和。

## 失败动作的比较边界

AUTO 的游标限制有限路线；共享账本另外比较已知失败的精确数值请求：模型、后端、配置、精度、模式，以及带基时的索引/状态。较短预算前缀仍可能合法让出；资源失败、预算退出和未知记录不冒充已知数值失败。账本满或快照拒绝只丢失记忆。

cover 的新主问题必须增加列，或严格缩紧对偶容差；失败 master 直接退出。BDA 内 NNLS blocked 集、活基变化、有限内层重试、PDHG 残差基线和面请求各有自己的消费条件，见[BDA 阶段契约](./pan-services.md)。
