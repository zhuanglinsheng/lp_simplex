# PDS 慢在哪里：分阶段归因与实现复核（2026-10-26—28）

2026-10-28 最新结论见 §13.10：本机 pds-100 的普通 Release、纯 Dual 整进程墙钟对照为 772.410 秒 / 38.123 秒（新版三轮中位数），约 20.26 倍。新版三轮的目标、168596 工作及残差一致。该结论只覆盖这一个案例及明确列出的旧版基线，不代表九例 PDS 全集或所有平台；后续 PDS 全集已验证 9/9 PASS，见[正式报告](../benchmarks/pds.md)；Railway 仍未恢复，数值候选未提交。

2026-10-27 状态：按用户要求暂停 PDS／Railway 求解及排队任务。本次追加分析只读取已保存的轨迹和参考解、检查矩阵、运行固定向量内核实验及纯 presolve，不运行 PDS／Railway 求解。代码保留在 main 的未提交工作区；20 倍是目标，尚未实现或验证。历史性能目录仅保留基准测试 Markdown；中间实验文件不作为仓库交付。

主要耗时在求解阶段，尤其是 PDHG 的大量迭代与可行性收敛；不是 presolve 自身执行慢。不过，当前 presolve 的结构削减能力明显落后，而且预处理会改变后续迭代轨迹，不能把它视为完全无关。

本轮没有调整默认算法、容差、预算或数据集特判。本文记录成功、超时和排除的对照；中间实验文件按用户要求清理；[此前 AUTO 修复候选及反例](pds-auto-review-2026-10-26.md)另行保留。

## 2. pds-70 的完整 CPU 时间去了哪里

此前完整基线诊断在原 300000 工作预算内完成，允许最多 330 秒墙钟用于观察。总求解 CPU 时间 282.139 秒；以下分解全部来自同一次运行，避免交叉相除：

| 阶段 | CPU 秒 | 占总求解 CPU |
| --- | ---: | ---: |
| presolve | 0.368 | 0.13% |
| AUTO 初始 Dual 探索 | 24.596 | 8.72% |
| 原生 BDA 内的 PDHG | 256.971 | 91.08% |
| 原生阶段其他工作 | 约 0.101 | 约 0.04% |
| 其余准备、交接与审核 | 约 0.103 | 约 0.04% |

原生阶段总计 257.071 秒，已经包含 PDHG；表中没有把嵌套计时重复相加。即使让 presolve 耗时完全归零，同一求解轨迹的总 CPU 时间也只能减少约 0.13%。

Dual 在 16384 个工作单位后因观测停滞让出，没有交出已验证可行点。其稀疏因子重建累计只有 0.044 秒／34 次，主要成本在基求解、更新、残差和比率等计算；不能仅因行数大就判断“矩阵分解是主瓶颈”。

随后原生界模型为 102033 行、376375 列、800103 个非零元，几乎立即得到初始可行点，但这个点的目标较差。PDHG 用 110465 步、51 次重启，最后通过 KKT 和原模型审核；期间恢复调用为 0/0。

本轮重跑仍然是同样的 Dual 16384 工作、PDHG 110465 步、51 次重启和 0/0 恢复；总工作 126849，最终原模型残差约 3.57e-11。CPU 329.289 秒，其中 PDHG 311.168 秒，约占 94.50%。墙钟为 366.949 秒，只是在本轮 420 秒诊断保护上限内完成；不能将它写成原正式 300 秒限时的 PASS。

相同步数并不意味着相同时间：CPU 频率、核调度、缓存争用和观测开销等都可能影响成本。机器并不独占，因此本轮不发布稳定加速比。

已有日志和本轮重跑一致出现以下当前点残差轨迹：

| PDHG 步数 | 当前点可行性残差 |
| ---: | ---: |
| 49153 | 2.58047e-3 |
| 57345 | 1.40335e-4 |
| 65537 | 5.14e-5 |
| 73729 | 5.14e-5 |
| 81921 | 5.14e-5 |
| 90113 | 5.14e-5 |
| 98305 | 3.52e-5 |
| 106497 | 2.07515e-8 |
| 最终认证 | 3.57832e-11 |

目标值看起来已经接近参考目标时，可行性仍不满足 1e-7 的要求；内部接收改进点还采用更紧的可行性余量，最优性审核也必须通过。不能用“目标差不多”替代这些条件。日志中的内部目标包含坐标变换，不能直接与原始目标混看。

[PDHG 代码](../../src/bda/simplex_pan_pdhg.c)用当前点和平均点的加权综合指标判断停滞；这个指标混合原始可行性和投影对偶分量。权重校准会重置这段历史。因此当前点的可行性平台并不必然触发恢复；本例事实上没有恢复。日志只展示当前点残差，不能由此声称所有内部候选都毫无进展。

八秒调用栈采样取得 6355 个主线程样本，全部位于 PDHG 调用内。其中主变量更新／列点积与残差更新两个大分支合计 6068 个样本，约 95.5%；只对应该采样窗口，不是全程精确计时。它支持热点在反复的向量及稀疏运算，而不是打印或预处理。审核、综合指标和权重计算也有成本，但没有在这个窗口主导。

当前实现已有单位系数短列编译、缩放代价缓存及迭代向量交换，保留补偿求和及非有限值检查；不能假设它还在每步重复做未优化的通用矩阵分解。是否受内存带宽限制、有效条件数多大，尚未用硬件计数或谱分析测量，本轮不作断言。矩阵系数本身均为绝对值 1，也不支持“系数跨数量级导致慢”的直接归因。

此前加入独立可行性观察的候选曾改善 PDS，但完整恢复给 qap15 引入超时；分层候选仍有 qap15 计时代价及未完成的全集验收。这些反例说明：发现机会与允许干预多少工作，必须分开处理。

## 4. 开／关 presolve 的实际对照

同一基线，每例每种设置各一次，累计工作上限 300000。墙钟保护上限为 420 秒，仅用于阶段归因；不是重新定义正式测试限时。所有已完成 AUTO 对照均通过 CLI 原模型可行性审核和显式参考目标检查。

| 案例与设置 | 求解 CPU 秒 | 墙钟秒 | PDHG 步数 | 结果 |
| --- | ---: | ---: | ---: | --- |
| pds-20，presolve 开 | 69.737 | 86.363 | 79617 | 完成，工作 96023 |
| pds-20，presolve 关 | 57.822 | 64.169 | 57601 | 完成，工作 74113 |
| pds-70，presolve 开 | 329.289 | 366.949 | 110465 | 完成，工作 126849；超过正式 300 秒 |
| pds-70，presolve 关 | 总计未知；最后进度已达 316.251 | 420.995 | 尚未进入 | 诊断超时，未得到初始可行点 |

pds-20 开启时原生模型较小，单步平均 CPU 成本也较低：PDHG 约 0.726 毫秒／步；关闭时约 0.796 毫秒／步。但是开启时需要更多步，抵消了单步收益。两种设置同时改变矩阵、边界、初始可行点与预条件权重，不能只把差异归给某一个因素。

具体地，pds-20 的初始权重从开启时约 891.6 变成关闭时约 18203.7；初始可行点来源也从已提供点变成 NNLS。它们是可复现的轨迹差异，不是已经完成因果隔离的根因。

pds-70 关闭后，初始 Dual 探索仍让出，原生初始化未能通过短 NNLS 得到可行点，转入内部的 Dual 可行性搜索。另一份八秒调用栈采样全部落在这个服务及其 Dual 内核，仍未到 PDHG。该服务不是第二个完全相同的优化请求：它采用仅求可行点的模式，不能单凭出现两次 Dual 就称为重复调度缺陷。

因此，关闭 presolve 对一个案例有利，对另一个案例却破坏了廉价初始化；没有依据做全局关闭或按数据集名称切换。两种开关也没有完成随机交替多次配对，CPU／墙钟数字不用于稳定性能收益声明。

额外的手动 `pan-bda` 对照在约 0.419 秒被主动停止并单独标记为 interrupted：它的默认标准形式与 AUTO 的原生界路线不同，不适合隔离 AUTO 前置 Dual 的成本。该中断结论保留在本文，原始中间文件已清理，也不计为完整限时失败。

这是当前输出仍含大量可削减结构的直接证据。但 pds-70 额外删掉约 46% 的行时，非零元只减少约 7.4%，列约减少 12.6%；不能按删行比例直接推算 PDHG 加速，也没有证明换成该输出就一定更好收敛。导出省略了不影响预处理结构的目标常数，不作为带参考目标的完整求解基准或等价性证书。

再运行我们自己的 presolve，可分别额外删除 pds-20 的 133 个、pds-70 的 500 个重复行，列数不变；第三遍结构不再变化。因此确有“代换以后暴露的跨阶段重复行未在同一次完整调用中全部闭合”的改进机会。但只多循环一遍不能解释 HiGHS 多删的约 1.97 万／4.73 万行。

[现有规则](../../src/presolve/simplex_presolve.c)先处理行列队列、平行行和支配，再进行[单列／双元等式代换及闭包](../../src/presolve/simplex_presolve_substitution.c)。代换能暴露新的平行关系；目前两个阶段没有完整地相互迭代到全局闭包。这一结构检查与第二遍的 duplicate-row 统计相符。集成更强闭包仍需正确组合 postsolve 映射，不能简单递归调用并丢弃原 journal。

HiGHS 对 pds-70 输出的 dependent-equations 搜索只删了 11 行，远少于总差距 47254 行；没有证据把主要差距归给缺少一次秩分解。日志也不足以精确划分其余各条规则的贡献，不能据此指定某条“万能缺失规则”。

另一个容易误读的诊断是 `Pan equality form ... selecting original`。它比较的是经典标准等式形式：pds-70 预处理收紧很多边界，若将每个有限宽度展开成附加行，标准形式会从约 26.2 万行扩大到约 47.2 万行。但当前主要耗时路径使用原生界表示，实际只有 10.2 万行，并未在那个 47.2 万行模型上跑 PDHG。不能把比较日志当作实际内存膨胀的证据。

## 6. 后续改进优先级与验收条件

1. 优先降低 PDHG 所需的有效工作量：独立观察可行性、对偶和综合指标，限制机会性修复的成本，只有经审核的点才交接。不能靠放宽容差、延长正式限时或提前接受近似目标取得通过；此前 qap15 反例必须保留。
2. 单独改进 presolve 的结构质量：先验证跨阶段平行行闭包，再定位更强的通用代换／聚合规则。每项分别测削减量、非零增长、边界及初始点变化，以及最终迭代数；用完整 postsolve 和原模型审核验证正确性。
3. 检查初始化与交接的复用机会。初始 Dual 的约 18～25 秒值得减少，但它只占本例约 5～9%，不能单独解释主要差距。原生可行性初始化的反例也说明，移除前置工作并不自动更快。
4. 数值策略候选必须覆盖 Netlib、不可行集、PDS 和 Railway；开发样本与冻结验证分开，回退案例另作交替配对。在稳定负载下同时记录 CPU、墙钟、工作计数及审核结果，不能只选择更快的一轮。

本轮完成的是归因分析，默认数值代码与完整基准报告保持不变。全部诊断和监测进程均已结束。

## 7. 2026-10-27：隐含上界中的搜索容差污染

这次比较旧 pds-70 的已保存 presolve 输出与当前代码的纯 presolve 输出。两者 A 的 CSC 索引和系数、b、c、下界及行类型逐项完全相同，均为 102033 行、369585 列、793313 个非零元；差别是 252371 个上界。这个比较没有执行优化求解，也没有用不同模型的时间推算收益。

旧实现把公开容差产生的 `tolerance*(1+|candidate|)` 当作隐含边界的扩张量，并沿推导链累积。旧输出中 252371 个上界距离最近整数在 `1e-8`～`1e-2` 之间，最大距离约 `0.003986`。当前输出相应偏差的最大值约 `9.48e-9`；这些输入中的整数结构只用于分析，生产代码没有取整规则。

例如旧上界 `513.0000514` 来自 `513 + 1e-7*(1+513)`。旧输出第 79809 行是零 RHS 的五元等式，其中第 78591 列系数为 +1，上界恰为 513；第 74067 列系数为 -1，上界却是 513.0000514。把这两个坐标置于各自上界、该行其他坐标置零，所得局部残差为 `5.1399999961e-5`。两个变量成本都为零。当前对应上界为 513 和 513.0000000000084，局部残差降到约 `8.41e-12`。另一个四元行中，链式填充后的两个上界为 513.0005670003529 和 513.0005156003014，也形成相同量级的差值。

在不超过 12 项的零 RHS 等式中，旧输出找到 10 对这种差值约为 `5.14e-5` 的相反符号上界组合；当前输出为零。这里构造的是单行局部角点，不声称整组坐标满足其他行，也没有保存旧 PDHG 平台时的完整迭代点。因此可以确认旧实现制造了这种残差尺度的盒角点，且与实际平台吻合；仍不能证明当时最坏残差恰来自这十个组合中的某一个。

针对性修正是让隐含边界按运算误差向外包围，而不是按搜索容差填充。误差界使用行项数、绝对活动量、RHS、已扣除项、系数、`DBL_EPSILON`／`DBL_MIN`，再以 `nextafter` 向外舍入；公开容差仅用于矛盾与有效收紧判断。不按数据集名称、整数性、行数或参考目标切换策略，不收紧最终验收容差，也不删除必要的舍入保护。

补充的分流守恒回归为 `-x0+x1+x2=0`，三个变量非负，x0 有有限容量。容量取 `.125/7/513/1024`，分别配 `1e-3/1e-7/1e-11` 容差，检查两个推导上界保留精确端点且不获得用户容差量级的填充。原有链式正负界、行的二次幂缩放及大数抵消用例仍保留。当前 presolve 测试包含 22 个子项；17 项相关 CTest 通过。这是数值正确性及机制验证，不是 PDS 加速证明。

## 8. 数据结构与活动面的新证据

预处理后的矩阵仍全部为 ±1，但不再仅有二元／三元列：

| 已保存输出 | 二元列 | 三元列 | 四元列 |
| --- | ---: | ---: | ---: |
| pds-20 | 85897 | 12985 | 1463 |
| pds-70 | 320942 | 43143 | 5500 |

这些二元列的两个系数均相反。只看二元列组成的行图，pds-70 有 11 个主要连通块，各约 8181～8321 行，其余为孤立点；三元／四元列还连接其他约束。它支持研究守恒网络块及耦合约束的分解，但不能把完整 LP 当作 11 个独立网络流。

当前短列计划只编译一元／二元 ±1 列，其余仍走通用补偿点积。一个只操作固定向量的 pds-80 矩阵内核实验，为额外 53120 个全单位系数列跳过恒为零的乘积余项，同时保留 Neumaier 求和。在该固定向量上结果逐位相同，六对反序实验中主变量更新内核的中位 CPU 时间从约 0.14745 秒降到 0.13962 秒，约快 5.3%。它不是完整迭代或求解加速比，不能外推为 20 倍；没有将这个实验加入生产代码。

此前实际矩阵上的 CSR 按行 gather 候选保持了求和顺序，却比已有融合 CSC scatter 慢约 2～3 倍；列更新／scatter 融合也曾更慢。因此没有证据支持直接替换 CSC 或继续堆融合循环就能获得数量级收益。当前没有硬件计数证据，不把缓存访问现象等同于已证明的带宽瓶颈。

读取已保存的 HiGHS 原始模型解，仅用于检查一个已知可行最优面的结构：pds-70 的 382311 个变量中，30630 个非零，按 `1e-7` 离界判断有 18082 个内点；pds-20 则是 105728／6536／5029。对应原始等式残差为零。这个解属于其他求解器，可能与我们的迭代面不同，也不能证明变量可永久固定。它说明高精度阶段继续全矩阵扫描很可能浪费了可利用的活动面结构；任何缩面都须允许释放误选边界，并经完整原模型 KKT 审核。

## 9. 算法工作量与 20 倍目标的实际约束

1. **消除人为精度长尾。** pds-70 在 65537～90113 步多次记录同一 `5.14e-5` 平台；旧边界角点能精确复现这个量级。当前边界修正先解决了可确认的实现问题，下一轮需在允许运行 PDS 后记录最坏残差行及点／界位置，直接核实平台是否消失。
2. **活动面恢复必须真正成功。** 旧 pds-80 的两次恢复记录均失败，分别只用了约 12／13 个累计工作单位，之后仍继续到十万余 PDHG 步。因此仅增加触发次数不够；应区分自由面残差不在列空间、触及另一侧界、混合 NNLS 未解出、步长审核拒绝和目标上限拒绝。旧的纯森林校正两次均不能覆盖残差，不能将其包装成有效优化。更合理的研究方向是联合处理守恒块与三元／四元耦合列，而不是只保留森林、忽略耦合残差。
3. **权重与重启的长尾。** 同一旧 pds-70 轨迹的原始步长权重从约 982 升到约 410697，后期再降到约 1.7；51 次重启中包含多次 8192 步窗口。权重改变后加权 merit 不能跨度量比较，物理可行性历史必须独立保留。持续降低加权 merit 不等价于绝对可行性改善。当前候选保留独立物理历史；仅可行性修复成功时保留可行改进点并继续原鞍点轨迹，避免因过早交接丢失仍在改善的乘子。
4. **初始化也必须降本。** 在已保存的 pds-70 预处理输出中，所有等式 RHS 为零，所有下界为零，6790 个不等式 RHS 非负，因此结构变量零点已经可行；原生 NNLS crash 实际也在 0 个迭代工作、约 0.03 CPU 秒得到可行点。AUTO 此前却先执行 16384 步 Dual 并耗费约 18～25 CPU 秒，未交出审核通过的可行点。便宜可行点的存在是调度的有用证据，但不能据此假定任何可行零点都值得优先用 PDHG 优化；跳过 Dual 需通过通用同类模型及跨数据集对照验证，当前没有新增此路线特判。

以一次完整基线的 282.139 CPU 秒计算，20 倍目标约为 14.107 秒；初始 Dual 的 24.596 秒本身已超过总目标。保持该前置阶段不变，即便 PDHG 耗时完全归零，整例提速也不超过约 11.5 倍。要达到 20 倍，需要同时减少前置探索和高精度阶段的工作，单独微调热点循环不够。

当前候选的 Netlib 控制中 dfl001 已通过，qap15 在 90 秒超时，cre-d 通过；这些结果不构成候选性能验收，更不构成 PDS 提速证明。20 倍尚未达到。PDS／Railway 后续求解仍按用户要求暂停；没有发布新正式基准，也没有提交或推送任何候选。下一轮测量应在分析后的独立改动上分别验证平台、恢复成功原因、迭代数及每步成本，最终仍需同一冻结版本的全集验收。

## 10. 2026-10-27：矩阵自由乘子修整候选

### 11.1 对 HiGHS 聚合规则做消融

读取本机 SciPy 私有 binding 的 HiGHS 1.12.0，并对照同版本[聚合器源码](https://github.com/ERGO-Code/HiGHS/blob/v1.12.0/highs/presolve/HPresolve.cpp)及[规则编号](https://github.com/ERGO-Code/HiGHS/blob/v1.12.0/highs/lp_data/HConst.h)。从当前预处理输出恢复原生不等式，移除仅为 BDA 引入的逻辑松弛列；输入为 28516 行／100345 列／216601 非零，全部来自同一个 pds-20 模型。只调用 `presolve()`，单线程，启用规则日志。以下均关闭 dependent-equations（bit 1024），从而隔离聚合而非秩搜索：

| --- | ---: | ---: | ---: |

### 11.2 我们漏掉了跨行隐含界

旧代换入口只允许一元／二元列，并要求某一条等式的盒区间同时蕴含被删变量上下界。扫描同一份 pds-20 预处理输出：85897 个二元列中，没有一个再满足这个局部条件；但有 14849 个变量的下界、上界分别由不同等式蕴含。

具体一列的界为 `[0, 351.00000000000574]`：一条等式的表达式区间为 `[-2208.0000000000273, 351]`，另一条为 `[0, 487.00000000003695]`。单看任何一条都不足以省略两端；结合保留行则足够。PDS 大量守恒网络弧与容量耦合使这种结构反复出现，这解释了为何此缺口在 PDS 上集中暴露。

候选允许来自不同当前等式的两个证明。新增证明限于 signed-unit 等式，端点采用 TwoSum 向外包围，精确零不引入额外填充；不根据容差、案例名、整数取整或参考目标授予约化。每次消元后更新可变矩阵和关联队列，重新证明后续候选，不能使用已删除行的旧证明。再用 `(r-1)*(d-1) <= r+d-1` 的无填充条件扩展到有适当短主元行的三／四元列；更长列仍由原有双元等式规则处理。

### 12.2 压缩基解恢复候选

对 `B=[K,0;H,-I]`，旧代码虽然只分解结构核心，恢复解时仍扫描零核心分量对应的整列，并额外清零即将被完整覆盖的输出。转置恢复也为每个核心列遍历全部系数。

### 13.2 对偶容差不能重复支出

观察发现，较早一次重分解后的成本修补幅度约 9，后期约 31830；列界宽度分别为 493 和 57，不能归因为窄界。首次大修补时 KLU 的 U 对角比为 1（该指标不是完整条件数），基驻点绝对残差约 1.46e-11，重分解前后参与定价的非基检验数与独立 CSC 重算相差约 1.46e-11。固定变量不参与符号可行性／增量维护，不应拿其缓存检验数衡量这项误差。

继续观察首次违约，定位到 Harris 第一遍：已有轻微负的有符号检验数先被截为零，随后又以零加整份对偶容差计算松弛断点，相当于每次换基重新补足已消耗余量。连续小透支会超过容差，随后该列被候选过滤排除，违约进一步扩大。修复保留原有有符号检验数计算松弛断点，只对主断点截零；第二遍不再以比值空间的 tie epsilon 扩大可行性窗口。列系数大时，比值小量不能无条件转化为合法的检验数余量。

两列独立回归在旧代码失败、修复后通过，覆盖上下界、三种系数尺度和三种对偶容差。没有 PDS 名称、目标或时间分支。181 项 Release 检查全部通过。
