# CSC sparse dual revised simplex 性能测试

本文记录仓库内 CSC sparse dual revised simplex 对 NETLIB 模型的性能与数值正确性测试。正式性能集合固定为 7 个曾经需要约 1–10 秒的模型，以便比较算法和数据结构优化前后的变化。

## 测试环境

- 系统：Darwin 25.5.0，arm64
- 编译器：Apple clang 21.0.0
- 构建目录：仓库内 `build/`
- 构建类型：Release，`-O3 -DNDEBUG`
- 算法：`dual-revised`
- 最大迭代数：300000
- 计时范围：读取 MPS 和分配解向量之后的求解阶段 CPU 时间
- 正确性判断：求解成功，且目标值满足绝对/相对混合容差 `1e-7`

当前基分解后端是仓库内实现的稀疏 LU。主要机制包括 CSC 系数存储、双边基矩阵平衡 `R B C`、阈值 Markowitz 主元选择、product-form eta 更新、BLAS AXPY/DOT 更新链、dual steepest-edge 权重递推，以及按离基行惰性精确校准 DSE 权重。

构建和单模型测试命令如下：

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j2
build/tools/test_netlib \
  --algorithm dual-revised \
  --iterations 300000 \
  data/netlib/feasible/25fv47.mps
```

设置 `LP_SIMPLEX_PROFILE=1` 可以输出基分解、FTRAN、BTRAN 和比率检验的内部 CPU 时间；正式计时未启用该选项。

汇总结果：

- lp_simplex 的 7 模型中位时间之和为 **2.905458 秒**；
- 优化前同一集合的中位时间之和为 31.880 秒，当前加速为 **10.97x**；
- Gurobi 仓库参考时间之和为 0.728129 秒，当前总时间是参考值的 **3.99x**；
- 7 个模型全部通过目标值校验，最大 primal residual 为 `1.46e-11`，最大 dual residual 为 `3.69e-13`。

## 优化效果

| 模型 | 优化前（秒） | 当前（秒） | 加速比 |
| --- | ---: | ---: | ---: |
| `25fv47` | 2.315 | 0.459931 | 5.03x |
| `degen3` | 10.369 | 1.022246 | 10.14x |
| `ganges` | 4.416 | 0.215122 | 20.53x |
| `scfxm3` | 1.920 | 0.223484 | 8.59x |
| `sctap3` | 5.200 | 0.195917 | 26.54x |
| `ship12l` | 2.760 | 0.210654 | 13.10x |
| `woodw` | 4.902 | 0.578104 | 8.48x |

主要收益不是来自放宽容差。动态 Markowitz 降低了 LU fill-in；双边平衡改善了大尺度差异模型的主元质量；惰性精确 DSE 消除了重分解后对每一行求一次 BTRAN 的全量权重重算；BLAS eta 更新则使较长的 product-form 更新链保持高效，从而减少昂贵的重新分解次数。

## `maros-r7` 结构对偶化

`maros-r7` 有 3136 个等式、9408 个变量和 151120 个非零元。其中 6272 个变量是成对出现的单例列：每个等式各有一个正单例列和一个负单例列，二者非负且具有正目标成本。原问题可以写成

\[
\min_x c^T x + \sum_i \left(c_i^+u_i+c_i^-v_i\right),
\qquad Ax+a^+u+a^-v=b,
\qquad x,u,v\ge 0.
\]

预求解器在完整验证该结构后构造其对偶：原等式对应有上下界的对偶变量，非单例原变量对应对偶不等式。求解后，通过对偶模型的行乘子恢复原非单例变量，再按每行残差恢复正负单例变量。恢复结果会在原始 9408 变量模型上重新检查变量界、等式残差和目标值。

同一 Release 构建下独立运行 3 次：

| 模型 | 迭代数 | lp_simplex 中位数（秒） | Gurobi 仓库参考（秒） | 参考比值 | primal residual | dual residual |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| `maros-r7` | 1864 | 2.280840 | 0.239771 | 9.513x | 2.18e-11 | 0 |

结构对偶化前，`maros-r7` 使用原始 9408 列模型求解约需 25.67 秒，其中约 81% 用于稀疏 LU 重分解。结构对偶化把迭代数从约 4358 降至 1864，并将时间降低约 11.25 倍，进入 Gurobi 仓库参考时间的 10 倍以内。

- `qap12`、`qap15`：MPS `ROWS` 字段解析错误已经修复，不再以 0 次迭代和目标值 0 错误返回成功；当前在 8 秒回归时限内未完成，因此不计入性能或正确求解统计。

## Gurobi 数据的可比性

Gurobi 时间来自仓库中的 `data/netlib/feasible_gurobi_1e-8.csv`。仓库只说明参考目标值和预求解结果由 Gurobi 10 产生，没有记录处理器、线程数、参数和计时边界。当前机器上的 `gurobi_cl` 因缺少许可证返回 Error 10009，无法补充同机结果。

因此，表中的 Gurobi 比值用于观察数量级，不能视为严格的同机 benchmark。严格对比仍需要在相同硬件、线程数、原始 MPS、预求解策略和计时范围下重新运行两者。
