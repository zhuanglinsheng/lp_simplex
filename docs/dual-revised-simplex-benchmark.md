# Sparse dual revised simplex 基准测试

本文记录当前 `lp_simplex` sparse dual revised simplex 在 30 个 NETLIB feasible
模型上的正确性和求解性能。

## 测试目标

测试集合覆盖小型问题、宽矩阵、长 eta 更新链、强退化模型和持续 1–13 秒的
大型问题。基准主要回答三个问题：

1. 当前算法能否在统一迭代上限内正确求解全部 30 个模型；
2. 总求解时间和迭代量是多少；
3. 与仓库中保存的 Gurobi 参考时间相比，主要性能差距集中在哪里。

## 测试环境与口径

- 测试日期：2026-08-08；
- 系统：Darwin 25.5.0，arm64；
- 编译器：Apple clang 21.0.0；
- 构建目录：仓库内 `build/`；
- 构建类型：Release，`-O3 -DNDEBUG`；
- 算法：`dual-revised`；
- 最大迭代数：300000；
- 计时范围：MPS 读取和解向量分配完成后的求解阶段 CPU 时间；
- 正确性标准：求解器成功返回，目标值满足相对/绝对混合容差 `1e-7`；
- 性能剖析：关闭 `LP_SIMPLEX_PROFILE`，避免内部计时影响正式结果。

当前求解路径包含模型所有的零复制 CSC/CSR 视图、稀疏 LU、product-form eta
更新、双右端 FTRAN、dual steepest-edge、CSC/CSR 混合稀疏定价、Harris ratio
test、bound flipping、Pan 退化控制和紧凑基分解。测试使用仓库中的当前默认
策略，没有为单个模型设置专用参数。

单模型复现命令如下：

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j4
build/tools/test_netlib \
  --algorithm dual-revised \
  --iterations 300000 \
  data/netlib/feasible/cre-b.mps
```

## 汇总

| 指标 | 结果 |
|---|---:|
| 正确求解 | 30/30 |
| 总迭代数 | 118986 |
| lp_simplex 总时间 | 40.909731 秒 |
| Gurobi 参考总时间 | 4.246255 秒 |
| 总时间相对 Gurobi | 9.634x |
| 单题处于 Gurobi 参考 10 倍以内 | 24/30 |

全部 30 个模型均通过目标值校验，没有出现迭代上限、错误 infeasible、错误
unbounded 或精度失败。

总时间主要由 `cre-b`、`cre-d` 和 `stocfor3` 构成。三题合计
**24.850640 秒**，占全部求解时间的 **60.74%**。因此总体性能已进入
Gurobi 参考总时间的十倍以内，但大型强退化模型仍是主要差距来源：

- `stocfor3` 为 Gurobi 参考时间的 48.028 倍；
- `wood1p` 为 32.671 倍，并产生集合中最多的 27241 次 pivot；
- `cre-b` 为 20.369 倍；
- `fit2p`、`cre-d` 和 `qap8` 分别为 13.813、12.058 和 11.920 倍。

这些模型同时表现出较长退化序列、较高 pivot 数或较重的稀疏基更新成本，
说明后续优化的主要空间仍在退化 pivot 数量、长更新链和 reinversion，而不是
小模型的固定开销。

## Gurobi 参考数据说明

Gurobi 时间来自仓库中的
`data/netlib/feasible_gurobi_1e-8.csv`。该文件记录了 Gurobi 10 的目标值和
求解时间，但没有记录处理器、线程数、参数、预求解设置和完整计时边界。
当前机器上的 Gurobi 没有可用许可证，因此未能进行同机重新测试。

因此，“相对 Gurobi”用于判断数量级和定位热点，不应视为严格的同机速度比。
尤其对 `afiro`、`agg` 等毫秒级模型，启动方式和计时边界足以主导结果；这些
模型中低于 `1x` 的数值不能据此解释为当前求解器普遍快于 Gurobi。严格对比
需要在相同硬件、线程数、原始 MPS、预求解策略和计时范围下重新运行两者。
