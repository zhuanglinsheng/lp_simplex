# Sparse dual revised simplex 全量 NETLIB feasible 基准测试

> 这是 2026-08-08 对当时提交状态的历史快照。后续 presolve、dual、basis 和
> 文件结构已经变化；表中的迭代数、通过率与耗时不能代表当前工作区。当前
> 算法行为以 [整体算法说明](./algorithm.md) 和源码为准。

本文记录当时版本的 `lp_simplex` sparse dual revised simplex 对仓库中全部
114 个 NETLIB feasible 模型的端到端正确性与性能测试。

## 测试环境与口径

- 测试日期：2026-08-08；
- 系统：Darwin 25.5.0，arm64；
- 编译器：Apple clang 21.0.0；
- 构建目录：仓库内 `build/`；
- 构建类型：Release，`-O3 -DNDEBUG`；
- 算法：`dual-revised`，使用当前默认控制器；
- 最大迭代数：300000；
- 单题墙钟上限：1000 秒；
- 计时字段：`test_netlib` 报告的求解阶段 CPU 时间，不包括 MPS 读取和解向量分配；
- 正确性：成功返回且目标值满足相对/绝对混合容差 `1e-7`；
- 正式运行关闭 `LP_SIMPLEX_PROFILE`，模型按文件名顺序串行执行。

单模型复现命令：

```sh
build/tools/test_netlib --algorithm dual-revised --iterations 300000 data/netlib/feasible/afiro.mps
```

全量运行还对每个进程施加 `gtimeout --signal=INT 1000`。TIMEOUT 行没有迭代数、残差或 solver CPU time，因为进程被外部墙钟限制终止，求解器没有返回结果。

## 参考时间说明

Gurobi 时间与目标值来自仓库中的 `data/netlib/feasible_gurobi_1e-8.csv`。当前机器没有可用 Gurobi 许可证，因此本轮没有同机重跑 Gurobi。参考文件没有完整记录硬件、线程数、参数、presolve 设置与计时边界，所以比值用于数量级判断和热点定位，不是严格的同机速度比较。

`forplan` 旧参考目标值经 SCIP 10.0.3 / SoPlex 8.0.2 对原始 MPS 独立复核后已修正。
